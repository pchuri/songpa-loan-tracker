# songpa — 송파구립도서관 대출 현황 조회

`songpa` 명령어로 등록된 계정들의 대출·상호대차·예약 현황을 읽는다. 조회만 하며 도서관 홈페이지에서
아무것도 바꾸지 않는다.

## 전제 조건

- `songpa`가 설치돼 있어야 한다: `uv tool install git+https://github.com/pchuri/songpa-loan-tracker`
  (설치 확인: `songpa --version`)
- 계정이 등록돼 있어야 한다: `songpa accounts list`. 없으면 사용자에게 직접 `songpa accounts add`를
  실행해 달라고 안내한다. **비밀번호를 대화로 받거나 명령줄 인자로 넘기지 않는다.**
- splib.or.kr에 직접 닿는 네트워크에서만 동작한다. 이 명령은 사용자 PC·휴대폰처럼 로컬에서 도는
  에이전트에서만 쓴다. 클라우드 샌드박스나 회사 VPN에서는 접속이 막혀 실패할 수 있다.

## 사용법

```bash
songpa --json                 # 전체 계정 (분석·답변용으로 권장)
songpa --json -u 홍길동       # 특정 계정만 (이름이나 아이디, 여러 번 가능)
songpa                        # 사람이 읽는 요약
songpa --html                 # 카드 화면을 브라우저로 열기 (사용자가 화면을 원할 때)
```

종료 코드: `0` 성공, `1` 일부 계정 조회 실패(결과는 출력됨, 다른 계정 결과는 유효), `2` 계정 미등록·
잘못된 옵션·같은 아이디 중복 등록.

## JSON 읽는 법

```json
{
  "fetched_at": "2026-10-05T09:30:00",
  "accounts": [
    {
      "label": "홍길동",
      "name": "홍길동",
      "book_count": 3,
      "interlibrary_count": 2,
      "ready_for_pickup_count": 1,
      "books": [
        {"title": "...", "status": "loaned", "due_date": "2026.10.07", "days_left": 2,
         "transit_status": null, "is_interlibrary": true, "library": "거마", "providing_library": "위례"}
      ],
      "reservations": [
        {"reservation_id": "1001", "title": "...", "library": "잠실", "ready_for_pickup": true,
         "pickup_deadline": "2026.10.08", "rank": null, "waiting_count": null, "reserved_date": "2026.09.30"}
      ]
    }
  ],
  "complete": true
}
```

- `books[].status`
  - `loaned`: 대출 중. `days_left`가 음수면 연체, 0이면 오늘 반납. 반납일을 못 읽으면 `days_left`가
    `null`이고 `due_date`에 사이트 글자가 그대로 들어 있다.
  - `ready_for_pickup`: 상호대차 책이 `library`(수령 도서관)에 도착. 찾아와야 한다.
  - `in_transit`: 상호대차 신청·이동 중. `transit_status`에 사이트 상태(`발송`·`요청중`·`신청중`).
- `is_interlibrary`: 상호대차(책솔이 포함) 여부. 상호대차 대출은 `library`가 수령·반납 도서관,
  `providing_library`가 책을 보내 준 도서관이다.
- `book_count`·`interlibrary_count`는 데스크톱 앱·아이폰 위젯의 `대출권수 (상호대차)` 표시와 같은 기준이다
  (도착·이동 중인 상호대차 건 포함).
- `reservations[].ready_for_pickup`이 true면 예약한 책이 도착해 `pickup_deadline`까지 찾아가야 한다.
  아니면 `rank`가 대기 순번이다.
- 계정에 `error`가 있으면 그 계정은 조회 실패다(비밀번호 오류, 접속 실패, 세션 이상 등). 다른 계정 결과는
  정상이다. 실패한 계정의 `book_count` 등 0은 "없음"이 아니라 **"모름"**이다(`partial: true`).
- `partial: true`(계정)·`complete: false`(최상위)면 합계를 확정치로 말하지 않는다. 이유는 계정의
  `warnings`에 있다(예: 마지막 쪽 전에 빈 쪽, 반복 페이지, 쪽수 상한 50 도달, 읽지 못한 행, 첫 화면 대출 수보다
  목록이 적음, 다른 계정과 같은 회원 표시). 목록은 페이지 표시를 따라 끝까지 읽고, 잘리면 이렇게 드러낸다.
- `books[].possible_duplicate: true`: 대출 중인 책과 **제목만** 같은 진행 중 상호대차다. 같은 권인지 확인되지
  않아 따로 보여 준다. 같은 권으로 묶는 것은 등록번호와 제공 도서관이 양쪽에서 하나로 확인될 때뿐이다.
  상호대차 상태가 바뀌는 중(입수→대출)에는 같은 건이 두 번 보이거나 빠질 수 있으니 확정으로 말하지 않는다.
- `reservations[].reservation_id`: 사이트의 예약 ID(없으면 `null`). 이미 같은 예약이 있는지 판단할 때 쓴다.
  같은 제목을 다른 도서관에 건 예약은 정상적인 별개 건이다.
- 상호대차 합계(예: 가족 합산 18건)는 관측에 기댄 사용 습관일 뿐 도서관 자격 규칙이 아니다.
  `interlibrary_count`는 상호대차 대출·이동 중·입수를 포함하고 복귀중은 뺀다.

## 본인 확인과 그 한계

- 계정은 한 번에 하나씩 조회한다. 같은 아이디(공백·대소문자 차이 포함)가 두 번 등록돼 있으면 로그인 전에
  거부한다. 서로 다른 계정이 같은 세션을 받으면 두 계정 모두 오류로 처리한다.
- 목록은 최종 주소가 요청한 페이지인지, 로그인 화면이 아닌지, 세션 쿠키가 바뀌지 않았는지 확인한 뒤에만 쓴다.
- 조회 시작과 끝에 첫 화면의 회원 표시를 비교해 도중에 바뀌면 오류로 처리한다. `label`은 화면용 별칭이라
  회원 이름과 같다고 가정하지 않는다. `accounts.json`의 계정에 선택 항목 `expected_name`을 적어 두면
  그 값과도 대조한다.
- 회원 표시가 비어 있으면 로그인 세션이 아닌 것으로 보고 그 계정을 오류로 처리한다.
- 서로 다른 계정이 같은 회원 표시로 보이면 두 계정 모두 `partial: true`(경고 포함), 최상위 `complete: false`다.
  동명이인인지 서버 쪽 세션 혼선인지 이름만으로는 구별할 수 없어서다(`expected_name` 대조도 이름 비교라 마찬가지).
  목록은 보여 주되 합계는 확정치로 말하지 않는다.
- 한계: 이름은 동명이인·표기 차이가 있을 수 있어 완전한 신원 증명이 아니다. 한 계정 안에서 서버 쪽 세션 혼선으로
  같은 이름의 다른 사람 화면이 오는 경우는 감지하지 못한다.

## 지원하지 않는 기능

- 연장, 예약 신청·취소, 상호대차 신청·취소, 재대출은 이 명령어에 없다(조회 전용).
- 요청이 오면: `songpa --json -u <이름>`으로 새로 조회 → `error`/`partial`이면 "알 수 없음"으로 다룬다 →
  기존 예약은 `reservation_id`, 제목+도서관으로 확인 → 실제 신청·취소는 사용자가 사이트에서 직접 →
  끝난 뒤 다시 조회해 확인. 이미 끝난 요청은 다시 하지 않는다.

## 답변 요령

- 날짜는 `fetched_at` 기준이다. "오늘", "내일"을 말할 때 이 시각을 기준으로 한다.
- 급한 것부터: 연체·오늘 반납 → 찾아올 책(`ready_for_pickup`, 예약 도착) → 반납 임박 → 나머지.
- 계정 아이디는 답변에 쓰지 않고 `label`로 부른다.
